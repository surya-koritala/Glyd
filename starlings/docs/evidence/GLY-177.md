# GLY-177 client response integration

Deferred authenticated responses reuse the existing grant and output machinery.
Admission sends no headers and releases the incoming connection permit. Slow
backend work can run without holding the shared authorization lock; JSON and SSE
use one gate. JSON results are bounded to 1 MiB. A nonblocking watch detects
disconnects, pipelined input, revoked/expired grants and request deadlines even
before backend output starts. It creates no thread and performs no database I/O.
The caller still owns bounded supervision, backend cancellation and trusted drain.

Review found that late maintenance could refresh an idle grant after its two-second
freshness limit if no output had observed the expiry. Refresh now checks validity
before and after policy validation; an expired grant never revives.

Synthetic loopback regressions cover deferred headers, release of incoming
admission, a 100,000-byte JSON result while the global policy lock is held,
disconnect, extra input, token revocation, drain, malformed/oversized JSON and
deadline expiry. Every failure prevents a late backend result from being sent.
The idle-grant regression expires freshness before maintenance without first
attempting output. Existing six-stream/admin/heartbeat and SSE boundary tests
remain in the required checks. No new dependency or real model run is involved.
