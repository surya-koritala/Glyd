## Delivered scope

`compute-security` implements protected root/device keys, five-minute invitation
files, pinned coordinator bootstrap, explicit CSR approval, atomic SQLite token
consumption and TLS 1.3 peer streams on separate control/data ALPNs. Original
implementation; no Exo or private Glyd code was copied. Project license undecided.
The [contract](../enrollment.md) documents APIs, records, limits and recovery.

Six security tests exercise:

- Actual enrollment over loopback TLS, device-key persistence, authority reopen,
  replay denial, and request/response bytes over both mTLS channels.
- Invalid token, altered/trailing CSR, expiry, concurrent consumption through two
  SQLite connections, replay after reopen, backward clock and removal of CSR CA
  privilege/SAN/usage requests.
- Wrong root, wrong coordinator identity and unapproved device fingerprint.
- A valid cluster certificate omitted from membership, and cross-channel ALPN.
- A real TLS 1.2 client rejected by the TLS 1.3 server; oversized frames and
  unsupported record versions rejected before use.
- Exclusive protected-file writes, traversal refusal, no raw token in SQLite,
  redacted parse errors, refusal of widened Unix modes/Windows ACLs, and Unix
  symlink/hard-link refusal.

## Review

Correctness/security review traced private file acquisition, input bounds, pinned
TLS, CSR signature verification, administrator fingerprint comparison, issuer-owned
certificate parameters, SQLite commit, response validation and peer stream exposure.
The fingerprint binds the stable public key and node ID, not a newly randomized
CSR signature. Request extensions cannot become CA privileges. Expiry is checked
again before consumption. Root/key consistency is checked on reopen. Raw TLS
configuration and pre-verification application streams remain private to the crate.

Complexity review: no custom crypto, certificate verifier, platform ACL code,
network framework or generic storage abstraction. SQLite supplies the transaction;
private-fs supplies handle-bound storage. The bounded 64-member scan remains direct.
No complexity finding requires another abstraction or dependency.

This is a self-review and automated test result, not an independent security audit.
The new private-fs 0.1.0 dependency is an explicit review risk; the inventory records
its contract and pin. Tests do not simulate physical power loss, hostile storage,
root/same-user compromise or a restored stale backup.

M1 remains incomplete: GLY-165 authorization/rotation/revocation, GLY-166 listener
budgets, GLY-167 daemon/CLI, GLY-168 membership/epochs and GLY-169 reachability must
finish and pass review before M2. Trust snapshots are not current per-operation
revocation. Leaf renewal is not implemented. No LAN service is advertised yet.
