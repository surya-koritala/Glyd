# Resource probe implementation

GLY-173 software slice: read-only host telemetry and pool reservation accounting.

The deterministic test replaces sampled host memory with a synthetic Apple pool:
CPU/GPU share one budget; 600 bytes reserved from 800 leaves 200, not 400; 801 is
refused. At the five-second boundary available capacity is zero. Backward wall
clock and suspend-like wall advancement expire the report. Linux ARM64 has only
one CPU pool. The CLI advertises no inference backend from host discovery.

Validation: warnings-as-errors workspace/all-feature Clippy and adapter test.
Four-platform CI and CLI checks provide platform execution evidence. No model,
GPU workload or Pi hardware was used for these resource checks. Backend
build/profile probing, discrete GPU telemetry and thermal policy remain open
within GLY-173; these changes do not close the complete task.

## Authenticated publication

Workers publish memory-only samples through their existing TLS heartbeats. The
coordinator's `cluster resources NODE` shows an authenticated, current observation;
the worker remains unavailable for inference. No new listener or framework is added.
The heartbeat thread reads only host/cgroup RAM and CPU affinity; full disk/sensor
enumeration remains in the explicit CLI probe.

Adapter regression validates production encoding with no inferred backend and
refuses aged observations. Registry regression injects a five-second-old sample,
repeats it with a fresh heartbeat, and verifies that it stays unavailable. A new
sample becomes visible; drain and revocation withdraw it. Invalid current
credentials also refuse the view. The real coordinator/worker process test checks
received node identity and coherent memory while retaining `schedulable=false`,
then exercises flood, restart, partition, drain and revocation.

Targeted local checks: two resource tests, one new registry diagnostic test and
the real daemon lifecycle test pass; workspace all-feature Clippy denies warnings.
Required four-platform CI remains the merge gate. The separate native API smoke
is recorded under `native/2026-10-12-m1max-cpu-api`; it does not qualify these RAM
estimates as native peak/request allocation budgets.

## Retained capture identity

`HostSnapshot` now assigns its snapshot ID once during memory collection, rather
than once per capability publication. Republishing a retained capture keeps its ID
and original observation timestamp while its sample age increases. A new
collection obtains a new ID; publication still refuses a stale capture at the
five-second boundary. This corrects capture identity semantics. The prior retained
timestamp and receiver checks already refused same-time or stale observations;
this change does not establish a previously exploitable freshness bypass.

Production heartbeats collect a new memory capture before each sample. Full local
disk/sensor/NVIDIA diagnostics retain the memory capture's original age, so slower
collection cannot renew its freshness. The coordinator routing pool already skips
previously seen snapshot IDs, and the core registry rejects changed contents under
a reused ID; those contracts remain unchanged.

Validation: `cargo clippy --workspace --all-targets --all-features --locked
--offline -- -D warnings` and `cargo test -p compute-adapters resources::tests
--locked --offline` passed with three resource tests. The regression checks stable
ID/time, increased age, distinct collection IDs and expired publication. Latest-head
platform CI is required before merge. No native/model/GPU work was run, and this
slice does not complete all of GLY-173.
