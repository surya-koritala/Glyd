## Delivered

Validated private configuration, native state/cache paths and exclusive profile
ownership. The foreground daemon supports coordinator, worker and client roles;
protected local init/prepare/approve/join/status/drain/stop/leave/invite/revoke flows
require no hidden configuration edits. The [operations guide](../daemon.md) provides
the two-machine procedure, internal API, failure behavior and current boundaries.

One bounded control loop owns policy and maintenance. Admitted threads handle
bootstrap/admin I/O; certificate issuance and reply delivery are separate so
network stalls cannot hold the control loop. Local clients verify server capability
possession before revealing their own credential. Drain rejects new model access,
cancels plans and retains in-flight memory until trusted completion. Stop/signals
join workers before validated transient cleanup; private identity/cache survives.

## Review

Correctness/security review covered all new CLI/config parsing, private state and
process lock ownership, stale endpoint cleanup, identity/config binding, approval
expiry/capacity, invitation transaction ordering, thread/queue admission, absolute
I/O deadlines, server impersonation, Windows pipe flushing, authorization during
drain, reserved memory accounting, signals and failed-start cleanup.

Fixes included blocking generic model callbacks during drain, proving the server's
capability before client disclosure, separating reply delivery from the authority
loop, retaining reservations until completion, and separating Windows default cache
from its coincident local data path. No TLS verification or resource limit was
weakened. Initial Windows CI exposed zero-byte reads from empty nonblocking pipes;
the adapter now waits within the fixed deadline and uses the native bounded
connector because the pinned generic adapter ignores Windows connect wait mode.
A delayed-proof/reply regression exercises this behavior. The separate Ponytail complexity review found no further necessary cut:
direct standard-library loops, file locks and bounded channels; reused native IPC,
JSON, crypto and signal/path libraries; no speculative runtime/framework/backend.

## Validation

Pinned Rust 1.97.1: formatting; default/all-feature Clippy with `-D warnings`;
default/all-feature tests and doc tests with warning-as-error flags. The final
Unix suite has 40 default / 41 all-feature tests; Windows omits the Unix SIGTERM
case (39 / 40). This includes 22 security tests and the native-path invariant.

Separate-process tests cover coordinator/worker/client enrollment with real TLS,
wrong fingerprint refusal, stalled TCP sender alongside responsive local status,
exclusive daemon ownership, drain and closed enrollment, revoke, local leave,
normal restart, forced-death restart, SIGTERM on Unix, malformed configuration,
occupied TCP bind, unexpected endpoint file and identity/cache preservation.
Library regressions reject a false admin-server proof before capability disclosure
and retain an in-flight 4 MiB synthetic reservation until local completion; new
worker admission, model callbacks, replays and cancelled output remain denied.

The existing CI cache gains an OS/architecture fallback so changed lockfiles can
reuse compatible dependencies; Cargo still validates fingerprints and every check
runs. Prior PR #5 Windows CI took 284 seconds on a cold cache. New exact-head times
and warning-log review belong in Linear, after all four jobs finish. No platform,
feature mode, fail-fast setting or five-minute job cap is removed.

## Remaining gates

Separate-process loopback evidence is not a physical two-machine LAN or a Windows
console-signal test. Local identity status is not remote authorization; membership,
epochs and revocation propagation remain GLY-168, discovery/reachability GLY-169.
Leave disables only the local profile; coordinator revoke is a separate command.
There is no inference/HTTP route, real active backend drain, model/GPU workload,
paid host or physical Raspberry Pi result. Linux ARM64 CI does not certify Pi
inference. License remains undecided. M2 waits for the remaining M1 tasks and review.
