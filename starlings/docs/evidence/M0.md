## Reproduction

Install the pinned toolchain and fetch the lockfile once, as documented in README.
Run formatting, default and all-feature Clippy with warnings denied, and default
and all-feature workspace tests. Run the CLI with `--features test-backend --
simulate` for the explicit simulation report. CI applies the same checks on Linux
x64, Linux ARM64, macOS and Windows; the default CLI rejects simulation commands.

Tests cover protocol, lifecycle, adapter framing and CLI/process behavior; current
counts are recorded in CI. Scenario groups:
whole requests, ordered pipeline, script-directed partial-prepare cleanup, cancellation during
work, expiry during work, disconnect and worker crash followed by scripted cleanup and stale capability replay.
Duplicate starts/completions, altered payload hashes, deterministic delay, late
cancellation and terminal-state checks are assertions within these groups.

## Correctness and security review

The input-to-execution path was reviewed from the framing cap through bounded
JSON, schema/type/semantic checks, operation digest and epoch, reservation,
session ordering, fake execution and response. Cancellation/expiry retain memory
until completion acknowledges the pending step; cancelled output is discarded.
Cached completion bytes are also invalidated after cancellation/expiry, including
a replay of an earlier successful completion. The process regression was observed
failing before this fix and passing afterward.
Recovery is scoped to node/cluster and a newer epoch after confirmed shutdown.
No peer-supplied wall clock renews a lease. Duplicate telemetry does not refresh
receiver-observed age. Old control sequences are explicitly rejected once outside the bounded replay window. Terminal records are reclaimed on admission pressure; recovery preserves bounded terminal diagnostics. Invalid inputs produce fixed errors without reflecting payloads.

All panics in non-test code are restricted to embedded fixtures/schema invariants
or fixed digest formatting, not malformed wire fields. No sockets, unsafe code,
credential handling, model downloads or native inference were added. The schema
validator cannot fetch external resources. Process reads and writes have watchdogs and apply replies carry request IDs; subprocesses are killed/reaped when their owning guard is dropped.

## Complexity review

The simulator uses standard-library pipes, processes, collections, channels and
injected time. Existing schemas supply shared record definitions through a local
registry; a duplicated command-schema copy was removed. Cached simulation
responses retain only output bytes, not repeated full worker snapshots. External
libraries are limited to documented parsing, schema, identity, timestamp and
integrity needs. No scheduler optimizer, generic backend framework, election,
persistent database, network service or GPU abstraction was added to M0.

## Limits and next gate

These checks establish protocol and simulated lifecycle behavior only. They do
not establish device throughput, partial model loading, numerical equivalence,
LAN security or crash-durable authority. The complete limits are in spec/README.md
and docs/decisions.md. Pi hardware/RAM and real inference remain unvalidated.
M1 may start only after the M0 PR, CI evidence and all task criteria are reviewed.


## CI time control

The first M0 cold run took 55 seconds on macOS, 68 on Linux x64 and 74 on Linux
ARM64. Locked dependencies add compilation work compared with the empty foundation.
The workflow now caches registry/build outputs by platform, dependency graph,
toolchain and workflow. CI-only profiles omit debug/incremental artifacts. All
checks still run on cache hits; no test or warning gate is bypassed. Cold and warm
run timings and completed-log inspection are recorded in Linear and the PR.

## GLY-224 evidence correction

The old 5,760-attempt trace reused one invocation and discarded outcomes; it was
removed. Its replacement executes 1,000 distinct generations, varies invocation
and session IDs, asserts operations and immediate replays, includes a 1,000-token prefill and 512-step decode
generation, one epoch without manual rollover and recovery after more than 300 leases.
A separate check fills the request table and verifies cleanup.

Process plans now have canonical nonzero self-digests, including whole-request
changes. A mismatched header plan digest must fail before execution. Fake-smoke
runs the simulator instead of comparing an echo to its input. The driver requests
rollback explicitly after failures: this tests worker cleanup, not autonomous
coordinator recovery. Disconnect/crash are distinct observed process outcomes
followed by the same cleanup path. All execution remains synthetic.
