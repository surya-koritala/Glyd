# GLY-169 implementation and review

[GLY-169](https://linear.app/getglyd/issue/GLY-169) builds on merged
[PR #7](https://github.com/Sigbound/glyd-compute/pull/7),
d96199cdc57c04acd1cb70e4f5decbab3ada1c91. Branch: gly-169-discovery-topology.
Linear records the PR head and exact-head four-platform CI evidence.

## Delivery

One to four explicit local coordinator listeners and routes; optional source binding;
sticky success/next-route-on-failure without changing the certificate pin; optional
IPv4-interface mDNS advertisement and bounded untrusted-hint scans; authenticated
local topology with source/interface, direction, freshness and network policy.
See [discovery contract](../discovery.md). No automatic enrollment, DNS fallback,
router configuration, public destination, backend or precision change exists.

## Review

Ponytail guided initial writing and a separate complexity pass. Reuse existing
registry heartbeats, freshness, protected config, TLS pins, process lock and shared
admission. Native interface enumeration and sockets use established libraries;
DNS-SD uses a pinned protocol library with async/logging default features disabled.
No custom DNS parser, routing manager, scanner, event runtime or background browser
is added. Removed the unused source-selecting enrollment API during review.

Correctness/security review traced all CLI routes, private config, role checks,
address policy, listener budget sharing, bootstrap before token transmission,
mutual-TLS registry pinning, failure rotation, absolute deadlines, freshness,
interface diagnostics, discovery filtering and shutdown. Directed observations do
not grant reverse reachability or authority. Public and ambiguous scoped addresses
are refused. No arbitrary TXT/service string reaches output.

## Checks

Pinned-toolchain format and warning-as-error lint; default/all-feature workspace
tests and doc tests. Unix has 50 default / 51 all-feature tests; Windows omits the
Unix SIGTERM case (49 / 50). Security tests total 29. No test is ignored.

New native process coverage: two active listeners, selected invitation address,
alternate join address, multicast-off operation, failed-route fallback, explicit
source, current topology and refusal to edit a running profile. New TLS coverage:
wrong coordinator refused without changing trust, fallback to the pinned coordinator,
source/interface inspection, route observation expiry. Address policy and DNS-SD
hint tests cover public/wildcard/multicast/zero/scoped/mapped inputs, extra TXT fields
and no implicit authority. Existing M0/M1 security and recovery tests remain.

A separate macOS loopback smoke check observed a local coordinator advertisement
through cluster discover, labelled trusted=false, then stopped the daemon cleanly.
It did not enroll a node or send discovery traffic on a physical LAN interface.

CI retains four platforms, both feature modes, warnings as errors, fail-fast,
cache reuse and five-minute jobs. Final head/timings/log diagnostics live in Linear.
[Full M1 review](M1.md) records cross-task acceptance and remaining evidence gates.

## Limits

Physical multi-interface/LAN/Pi and IPv6 scoped behavior are not qualified. mDNS
runtime is not exercised on every hosted CI platform; deterministic filtering is.
The library's internal cache is not a hard process-memory quota. The selected
interface and direct-address policy intentionally exclude public/global addresses.
No inference or performance result, paid resource, release or license decision.

Windows CI exposed a topology-response IPC failure. Local admin now sends bounded
256-byte Windows pipe writes under the unchanged absolute deadline. A 12 KiB
request/reply regression verifies exact bytes in both directions. The frame cap,
security proof and watchdog are unchanged; final platform evidence is in Linear.
