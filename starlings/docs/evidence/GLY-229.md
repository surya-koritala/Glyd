# Streaming authorization and admission

Local synthetic loopback test holds six authenticated SSE connections while three
authenticated registry exchanges and local admin status/stop exchanges complete.
Each stream delivers 20 events. Stop withdraws all late output. Incoming-client
permits return to zero while streams remain active; live grants have their own
32-entry limit. Separate admin/peer budgets are exercised in the same test.

The grant test holds the global policy lock while another thread performs 10,000
checks, proving the per-output path does not reacquire that lock or touch SQLite.
Measured local mean: 122 ns/check, macOS/aarch64, Rust 1.97.1, unoptimized tests.
This is the in-memory authorization path only, excluding serialization, socket I/O,
TLS, maintenance contention and inference. It is a diagnostic, not a throughput
claim. Reproduce with `cargo test -p compute-security --lib streaming -- --nocapture`.
Revoked/stale grants cannot revive and the 32-stream bound is checked. Invalid
events, exhausted output capacity and deadlines close the socket permanently;
subsequent event/finish attempts cannot publish bytes.

Validation: workspace/all-target/all-feature Clippy with warnings denied; targeted
grant/stream integration tests; full security regression suite before PR. Required
four-platform and dependency CI precede merge. No backend/model/GPU/Pi was used.

Integration limits: the daemon has not exposed generation routes. The caller must
bind request model to its trusted scope before response headers, maintain authority
at least once per second, enforce the live worker fence/lease, and cancel/drain the
backend on disconnect or output failure. The stream primitive does not claim those
later API/adapter acceptance checks are complete.
