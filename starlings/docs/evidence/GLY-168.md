# GLY-168 registry implementation and review

Issue: [GLY-168 / T04.2](https://linear.app/getglyd/issue/GLY-168).
Base: merged [PR #6](https://github.com/Sigbound/glyd-compute/pull/6),

Linear records the uploaded head, PR and exact-head four-platform CI results.

## Delivered

Authenticated automatic registry heartbeats on the existing coordinator port;
SQLite membership/boot/sample high-water marks; durable startup and worker-restart
epoch increments; protected remote boot/fence records; two-round-trip epoch
acknowledgement; expiring capabilities/link samples; offline/draining/revoked
status and `cluster nodes`. Devices advertise no inference capacity by default.

Existing plan authorization rejects stale stages/epochs. Secured-worker fencing
serializes authority changes with dispatch/output, cancels orphaned plans and
preserves in-flight reservations until trusted local drain. Epoch handoff preserves
replay tombstones and never restores KV state. See [registry contract](../registry.md)
for exact records, bounds, API wiring and integration obligations.

## Review

Correctness/security review traced enrollment and registry ALPN selection, exact
certificate membership, the narrowly scoped own-revocation reply, durable commit
ordering, exclusive state ownership, replay sequences, sample omission/repetition,
coordinator and worker restart, epoch/output races, clock jumps/suspend, partial
network failure, bounded I/O/threads, shutdown and orphan memory accounting.

Review fixes preserve sample high-water marks across restart and omission, hold
the fence through dispatch/output, keep draining and offline distinct, prevent
client-only restarts from fencing compute workers, recheck live credentials in
node status, and fail the daemon loudly on
registry persistence failure. A paired wall clock can shorten but never extend
monotonic freshness. Retry jitter reduces synchronized admission bursts. No
certificate verification, frame/admission budget or lease exactness check is weakened.

Ponytail guided implementation from the start and a separate complexity pass:
reuse SQLite, Rustls, standard-library locks/threads and existing core cancellation;
no framework, new dependency, consensus, scheduler or backend. Replaced a one-worker
collection with an optional weak reference and removed a non-atomic check helper
and redundant deadline reset. Global fencing on worker restart is the explicit
64-member ceiling; optimize only with measured restart-churn evidence.

## Validation

Pinned Rust 1.97.1: formatting; default/all-feature Clippy with `-D warnings`;
default/all-feature workspace tests and doc tests, warning-as-error flags. Unix
has 45 default / 46 all-feature tests, including 26 security tests. Windows omits
the Unix SIGTERM test (44 / 45). No ignored tests are added.

Native process/TLS evidence covers automatic heartbeat registration, worker death
and fresh boot epoch, coordinator outage and expiry, coordinator restart and
reconciliation, drain, own revocation delivery, anonymous and CA-valid unregistered
registry refusal, and preserved private state. Pure resource inputs and synthetic
4 MiB reservations cover stale/mutated sample rejection, independent sample expiry,
no freshness restored from durable state, client restart isolation, malformed
reports, epoch overflow, stale replies, clock/suspend guards, cancellation and
retained in-flight allocations. A concurrent epoch update waits until output
callback completion; no stale output can pass the subsequent gate.

All four CI platforms, cache validation, default/all-feature checks, fail-fast
matrix and five-minute job cap remain unchanged. No extra workflow is added.
Exact-head timings and completed-log diagnostics are recorded in Linear after CI.

## Limits and next gate

Loopback processes are not physical multi-machine LAN/suspend or power-cut evidence.
Model execution, backend drain, Pi inference, GPU performance and real link/resource
probes are not claimed. The daemon has no remote inference/control route. Model/token
policy replication and rotated-pin delivery must be integrated before those routes
are exposed. Registry heartbeats alone are not model authorization. Existing M0
worker history limits still apply. No automatic failover or cloned-profile recovery
is supported. License remains undecided; no paid resources or publication occurred.
GLY-169 and the complete M1 review remain before M2.
