# GLY-165 authorization implementation and review

Issue: [GLY-165 / T03.2](https://linear.app/getglyd/issue/GLY-165).
Base: merged [PR #3](https://github.com/Sigbound/glyd-compute/pull/3),
`f18c256582f3142da568e5b86ff5dc6075519361`. Branch: `gly-165-authorization`.
The issue records the uploaded head, PR and exact-head four-platform CI results;
local checks do not substitute for that gate.

## Delivered

Current membership and explicit per-model role permissions; controller-owned,
narrowly scoped client tokens stored only as hashes; new-key certificate renewal
with bounded overlap; persisted revocation; live TLS socket closure; and authorized
worker admission, cancellation, output publication and disconnected lease expiry.
No new third-party dependencies, daemon or inference backend. See the
[authorization contract](../authorization.md) for concrete APIs and integration gates.

The implementation uses the existing cryptographic, storage and lifecycle paths.
Complexity review removed duplicate membership scanning and a redundant activation
wrapper. A bounded policy lock and standard-library file lock replace separate
policy services or an extra locking dependency.

## Correctness and security review

Reviewed trust creation and refresh, peer registration after TLS, both local and
remote identity checks, mutation/dispatch serialization, token narrowing, model
binding to stored plans, replay ordering, permanent revocation, renewal key proof,
certificate overlap, crash ordering for coordinator keys, and in-flight drain.

Review fixes added a post-read membership check that clears denied data, fail-closed
connection/work cancellation on clock or storage failure, worker/local-stream
identity binding, and explicit lease-state gating of completed output. Backend
completion is a local-only call through the secured wrapper. There is no unsafe
code, disabled certificate verifier or production TLS 1.2 fallback.

Eleven security regression tests include the six existing enrollment/TLS scenarios
and added coverage for:

- Permission denial by default, role/model/action narrowing, token expiry and
  revocation, grant removal, protected token files, hash-only database storage,
  restart persistence and competing live-runtime rejection.
- Actual renewal over mTLS, fresh key and unchanged identity, old/new overlap,
  refused repeated rotation, expired old live credentials, and coordinator key
  selection after restart. Expiry is injected through isolated test databases;
  tests do not sleep for a real five-minute overlap.
- Revocation during TLS read and denial of subsequent artifact dispatch.
- Multi-stage plan cancellation after node/token/grant revocation, token expiry,
  clock rollback or disconnected lease expiry; memory retained until local drain;
  network completion refusal; replay and cancelled output denial; successful
  active output publication and completed-output denial after lease expiry.
- A correctly CA-signed but unregistered leaf rejected by the server.

Local validation uses pinned Rust 1.97.1: formatting, default/all-feature Clippy
with `-D warnings`, default/all-feature workspace tests and doc tests. The full
suite contains 25 default and 26 all-feature tests, including 11 security tests.
CI retains Linux x64, Linux ARM64, macOS and Windows, its five-minute job ceiling,
warning-as-error policy, cache, fail-fast matrix and stale-run cancellation.

## Remaining gates

This is a tested local library boundary. There is no production artifact endpoint,
remote policy replication, daemon timer or real backend cancellation yet. GLY-166
must harden routes/listeners and output queues; GLY-167 wires daemon/admin controls;
GLY-168 distributes current membership and integrates heartbeat/epoch/lease timers;
GLY-169 supplies reachability/discovery. Those tasks must preserve per-operation
and per-output checks. All M1 work must be reviewed before M2.

One plan has one client-token owner. Root rotation, role changes, stale-backup
recovery and automatic tombstone/old-key compaction are not provided. Existing
storage assumptions remain in force. No model, GPU, paid host or physical Pi was
used. No inference performance or hardware support claim follows from these tests.
