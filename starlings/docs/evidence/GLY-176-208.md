# Supervised external-service software checks

The shared adapter compiles without an inference runtime. Synthetic child-process
loopback tests exercise authenticated readiness, exact approved configuration,
nonstream and SSE text/reasoning/usage preservation, rejection of tool output,
backend crash and cancellation during a stalled response. The daemon/library
process remains alive. Strict output identity, finish ordering, usage bounds and
reasoning support are checked. No real model, GPU or external inference code runs
in these tests. ARM64 CI is software evidence only.

`cargo test -p compute-adapters --lib service --locked --offline` reproduces the
process tests. Workspace Clippy denies warnings and CI checks all four platforms
plus dependencies. See [service boundary](../service-adapter.md) for bounded
resources, trust assumptions and pinned future CPU qualification candidate.

This advances GLY-176 and GLY-208 but does not close their native acceptance:
backend version/profile attestation, pinned tokenizer/template inspection, measured
load/session memory, actual process-tree/device drain and direct/proxied conformance
remain required. Generation daemon/catalog pin integration and worker placement
remain GLY-171/172/173/177/178/209. Physical Pi remains GLY-210. No native capability
is advertised and no inference performance claim is made.
