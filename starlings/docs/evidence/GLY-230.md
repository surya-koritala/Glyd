# Whole-request worker lifecycle

The strict control schema now includes `start_request`: one fully resolved chat
request, one admitted session and one invocation. Core validates whole-request
placement, exact manifest identity and sampling consistency; existing authorization
still resolves the stored plan. A 1,000-prompt/500-output synthetic session uses
one invocation. Lifecycle tests cover exact replay, wrong model, mismatched limits,
completion, cancellation, lease expiry and backend failure. Reservations survive
in-flight cancellation until trusted local drain; late output cannot revive work.

`cargo run -p compute-protocol --example validation_cost --locked --offline`
measured 1,000 synthetic StartStep decode + repeated apply-validation passes on
macOS/aarch64, Rust 1.97.1, unoptimized development profile: mean 370,515 ns/pass.
This diagnostic excludes core transitions, TLS, transport and backend execution;
it is not a release-build latency benchmark or inference result. Reproduce with
the committed example; variation across machines/build profiles is expected.

M3 budget: target at most 1% of measured per-token stage latency for control/header
validation on each qualified backend/hardware row. Establish a release-build
baseline and replace repeated JSON schema/canonical hashing with session-bound
cheap header checks before the tensor data path. This is an engineering target,
not a measured achievement. Whole requests do no per-token schema validation.

Local validation: warnings-as-errors workspace/all-feature Clippy, ten core
lifecycle tests and six protocol contract tests. Native backends, streaming API,
tokenization/usage evidence and per-chunk authorization remain M2 integration.
No real model or GPU workload was run; no Pi hardware result is claimed.

The development simulator now dispatches independent whole requests with
`start_request` rather than tensor steps on a whole-request plan. Its separate
worker processes verify one execution on replay and withdrawal after release;
the existing two-stage tensor pipeline remains a separate scenario. Both CI
feature modes are checked.
