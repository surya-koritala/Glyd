# Read-only invitation outcome inspection

An expired response wait for a started invitation still has unknown outcome.
Generic cluster status cannot establish whether its token committed, and a
published file can outlive transaction rollback. `cluster invite-status FILE`
now checks the exact protected record against the current coordinator's name,
public key and CA, then the unexpired database row and allowed invitee role.
Drain/consumption/expiry/untracked tokens never report active. Missing or unsafe
input and authority mismatch fail rather than granting success.

The query uses existing protected parsing, key comparison and the clock floor
validated by the authority lock. It issues/consumes/extends no token and performs
no business-state SQL write. Its response is only `active=true/false`, with no
token, path, certificate or role details. Local worker/client profiles cannot
invoke it. Existing IPC budgets/deadlines and unknown-outcome semantics remain.
A negative/error observation never authorizes another mutation; this is not an
automatic retry or proof of future connectivity/enrollment.

The consolidated security regression covers committed persistence, no SQL/file
mutation, file-only rollback, tampered expiration/token/key, foreign authority,
forbidden database role, actual credential consumption, restart, expiry and drain.
The existing real-process roles/enrollment/drain/restart test verifies exact CLI
output before/after consumption and refusal on both worker/client profiles.
These are isolated software/control tests, not physical hardware or inference.

security regression (0.28 seconds) and the real-process role lifecycle regression
(8.28 seconds) pass. Durations identify these local software runs only. The first
