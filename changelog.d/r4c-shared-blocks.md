- A request that begins as another one does shares that start instead of running it again, on the models the description executor serves with paged keys and values: it names the other sequence's blocks (whole blocks of 16 tokens; the other may be finished and kept, or still running) and runs only the rest, in a slot of its own, so a conversation whose system prompt another has run starts where that prompt ends and neither loses anything. Gemma 4 and Muse Spark share any start; the Qwen3.5 layout shares a prompt another request has run to its end (its recurrent states are copied from there); Kimi-K3 and GLM-5.3-Flash share nothing. Requests share only within their cache scope (`cache_salt`).
- `glyd-engine bench` has requests that begin alike (`--loads same4k+250ms:8`, `--suite shared`).
