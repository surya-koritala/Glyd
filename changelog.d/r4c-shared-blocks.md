- A request that begins as another one does shares that start instead of running it again, on the models the description executor serves with paged keys and values: it names the other sequence's blocks (whole blocks of 16 tokens; the other may be finished and kept, or still running) and runs only the rest, in a slot of its own, and neither loses anything. A request whose start another is still running waits for it, while at least a chunk of the start is left to run, and then shares it. On an RTX 4080 with gemma-4-12B, eight requests with the same 4k start arriving together at a server that has not seen it have their first token in 1.37 s where it took 5.0 s, and make 298 tokens/s in all where they made 87 (`benchmarks/gpu/rtx4080-shared-starts-2026-11-22`). Gemma 4 and Muse Spark share any start, from a sequence that has grown no more than a chunk past it (their sliding layers give back the blocks before); the Qwen3.5 layout shares a prompt another request has run to its end; Kimi-K3 and GLM-5.3-Flash share nothing. Requests share only within their cache scope (`cache_salt`). `GLYD_ENGINE_KEEP=0` turns it off.
- A kept sequence that a request begins like but cannot go on in (a cut its sliding layers no longer hold, a recurrent model with no state kept there) is left as it is while a slot is free, for its own conversation's next turn.
- `glyd-engine bench` has requests that begin alike (`--loads same4k+250ms:8`, `--suite shared`).
- Anthropic's `cache_control` has an effect: what a request with a marker leaves in the cache is held before other requests' for the marker's time (5 minutes, an hour with `ttl: "1h"`) when the server needs a place, and never keeps a request waiting. Any request can ask the same with `cache_pin_seconds`.
