- DeepSeek-V4 is paged like every other attention model on the executor: its sliding window and its compressed entries (the attention's and the indexer's) live in the executor's block pools, a compressed group's block holding 16 entries (16 x ratio tokens). A sequence takes the blocks its tokens fill instead of a whole context's entries, so the page budget, preemption, swapping to host memory and prefix sharing apply to it. A start is found by name in whole blocks of every group: for DeepSeek-V4's ratio-128 layers, in steps of 2,048 tokens.
- A sequence swapped to host memory no longer holds up the next step: its copy runs beside the steps after it, and a step waits only for the part of the copy that reads blocks it takes (the first few blocks of each group are copied first).
- A sequence on 12-bit lossless KV pages is swapped in its 12 bits: each page moves as it is, with its escape chunks and raw slab, and is lent new ones where it is loaded (GPU library C API 21: `glyd_gpu_kv_image_bytes`, `glyd_gpu_kv_save`, `glyd_gpu_kv_load`). Before, its values crossed the link as bf16.
- Deterministic capacity on 12-bit lossless KV pages: a request is never refused because its keys and values compress worse than the calibration. Where the raw pool is short of a slab for every page the next pass writes, the newest request is paused (swapped or recomputed) and its pages' chunks and slabs go back to the pools; a request alone always fits.
- Not measured on a GPU yet.
