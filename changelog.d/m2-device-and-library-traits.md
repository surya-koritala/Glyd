- The engine reaches the GPU driver through one device-layer interface (`src/device.rs`: NVIDIA's driver, and HIP's runtime in an AMD build, behind the same trait), and Glyd's GPU library and cuBLAS through two more (`src/gpu_ops.rs`), so that another vendor's device layer, or a family of the library's operations moved into the engine's own kernels, is one implementation and not a search of the tree. Nothing changes on the GPU: every check gives the same verdicts as the tree before, and the logits fixtures the same bits.
- The engine decides itself which kernel, or the matrix decoded for cuBLAS, takes a packed product of a prompt's length on a GPU, reads the GPU's class from its name, and sizes the 12-bit KV cache's pages, pools and decode workspace, where it asked the GPU library before. `glyd-engine foldcheck` (a development build; in the GPU job) compares each answer with the library's for every GPU class the library knows.
- `glyd-engine/docs/design/kernel-libraries.md`: which operations use NVIDIA's libraries and which Glyd's own kernels, per GPU, with the numbers measured so far and the test that decides each open row; on an A100 cuBLAS multiplies a decoded matrix 2-10% faster than Glyd's own dense product, and keeps it.
- The engine runs the GPU library's operations with its own kernels (the packed layouts' unpacking, the experts' plan, the step products of 1 to 64 tokens and the prompts' products, the grouped experts' products, the 12-bit KV pages' write, unpack, gather and attention, the lossless FP8 format and its products), compiled from the GPU library's own source into the engine (`gpu/glyd_gpu_kernels.h`, `glyd-engine/kernels/fold.cu`), not by calling the GPU library; `glyd-engine foldcheck` compares every output with the library's. A development build's `GLYD_ENGINE_FOLD=lib` runs the library's instead.
- The decode attention's workspace puts its partial outputs on a 16-byte line: a batch whose sequences, heads and splits multiplied to an odd number faulted with a misaligned address (the C API is 23).
