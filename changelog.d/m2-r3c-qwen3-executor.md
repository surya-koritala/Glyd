- Qwen3 dense runs on the description executor, the one that runs Gemma 4, Qwen3.5 and the other families (R3c, #139): its layers are lowered from config.json to the shared operations (the attention kind, the gated SiLU MLP, the RMS norms), and the same lowering takes every Llama-style config the description builder reads (Llama, Mistral; Llama 3's scaled rope and Qwen2's attention biases are refused, named). The hand-written Qwen3 engine and what only it used (its KV cache tables, `kvtest`, `stress`, `recompute`, `rowcheck`, `batchcheck`, `kvcal`, `calcheck`, `score`, `info`) are removed.
- `glyd run` and `glyd serve` take Qwen3 at the kestrel, swift and wren levels as well as penguin. A server takes up to 64 users at once (it took 8), each user's keys and values in pages; the 12-bit lossless pages are there with GLYD_KV=lossless, as for Gemma 4. Without it the keys and values are bf16 (lossless, 2 bytes a value where the old engine's cache took about 1.6), so `fit` plans less context for Qwen3 on the same GPU: Qwen3-8B at penguin on an RTX 4080 SUPER, 8,192 tokens take 1.21 GB of keys and values (0.96 GB before); with 4 users the context planned is 5,888 tokens (7,424 before). Speed against the old engine: not measured yet.
- A Qwen3 model packed by an earlier glyd for its own engine (glyd-v4 or glyd-v3 with `engine.safetensors`) is packed again in the cache on the first run (a glyd-v7 directory); a directory you packed yourself is refused with the words to pack it again. `glyd run Qwen/...` in a terminal chats without serving the page at a URL, as the other families do.
