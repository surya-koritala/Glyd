- A prompt finds the start it shares with any earlier request, whether or not a sequence still holds it, on the models the description executor serves with paged keys and values (Gemma 4, Muse Spark): the executor's blocks are found by what they hold (a name for each full block of 16 tokens, of its tokens and all before them), and a block no sequence holds stays until its memory is needed, the oldest first. So a conversation's system prompt is shared with a new conversation after the first has grown far past it or has ended, a conversation whose slot was taken finds its own blocks at its next turn, and a sequence sent back to wait for memory does not run its prompt again.
- A block's name is the first 16 bytes of SHA-256 over the name of the block before it and its 16 token ids (`kv::block_hash`); the dense engine's page cache uses the same names in place of its 64-bit keys.
