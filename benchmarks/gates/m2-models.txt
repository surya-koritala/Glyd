# DRAFT for the owner's review (2026-11-25): the M2 gate's pinned list per GPU. Nothing here has been run on a GPU; every number is the planner's, not a measurement.
# The gate (epic #121): a pinned per-GPU list (the smallest checkpoint of each family that the plan fits) serves 64 concurrent requests through one scheduler on an
# RTX 4080 SUPER and an L4, with logits matching the CPU Ref backend. This file says which models, at which levels and contexts, for each GPU; the run that checks it comes later.
#
# How the rows were chosen
# - Families: the rows of the engine's support table (src/support.rs): plain dense, Qwen3.5 layout, Nemotron-H layout, Gemma 4, Kimi-K3, GLM-5.3-Flash, GLM-5.3, DeepSeek-V4, Muse Spark,
#   Qwen3.8-Flash-Next. A family with no checkpoint the planner fits on a GPU has a NONE row with the planner's own refusal: why a model does not run is part of the product.
# - Models released in the last six months only (createdAt on the Hub), from the Hub's newest models of each publisher (the 40 newest of each of Qwen, google, deepseek-ai, moonshotai, zai-org,
#   meta-llama, mistralai, microsoft, openbmb, LiquidAI, stepfun-ai, MiniMaxAI, openai, XiaomiMiMo, inclusionAI, CohereLabs, ibm-granite, baidu, tencent, and nvidia's 100 newest). Of a family's releases
#   that the engine takes (`glyd-engine supports`) in that set, the smallest that fits; "smallest" is among those, not every model on the Hub. Cutoff 2026-05-20, as M1's list:
#   google/gemma-4-12B-it (2026-05-23) is six months and two days old today; it is the model of the product path's smoke and the smallest Gemma 4 the engine runs (the E2B and E4B releases
#   are refused: per-layer embeddings are not in the engine yet). The owner decides.
# - Fits: `glyd-engine fit MODEL[:LEVEL] --machine rtx4080s|l4` on the CPU build (rtx4080s: 15.2 GiB free of 16.0, 56 GiB of RAM; l4: 22.0 GiB free of 24, 14 GiB of RAM). `fit` counts users
#   for the plain dense kind alone, so the 64-user plans of the others are the planner's `serve --users 64` sizing (`plan::planned` called as `serve` calls it, which is where the lossy
#   paths and Gemma 4 without its draft model count them), at 1,024 and 4,096 tokens of context a user.
#
# Users: 64 on every row (the gate). Contexts: 1,024 and 4,096 tokens a user on every row (the pool the planner sizes holds that for each of the 64 users).
# Levels: the first is the least lossy level the planner holds; the others are levels it also holds (those the plans below were made for). A * marks a level where the planner does not count 64 users (see "Planner gaps").
# The plan: weights on the GPU + the KV pool of the 64 users (GiB), and in brackets the GPU memory the plan needs in all (with the engine's work and its reserve) of the GPU's free memory; at 1,024 / 4,096 tokens.
#

# Planner gaps the run has to cover (found while making this list; the plans above are what the planner says, not what a GPU holds)
# - The dynamic route (the Qwen3.5 layout at penguin) sizes one sequence: the WeMM-Ecom-0.8B penguin row has no 64-user plan. Its lossy levels count 64 (the kestrel and wren figures); penguin's
#   weights are 0.4 GiB above kestrel's.
# - The experts-in-RAM plan of the Nemotron-H layout (the 4080 SUPER's) sizes one sequence too: 64 users are not planned there. On the L4 every expert is on the GPU and 64 are counted.
# - Gemma 4 sizes 64 users only without its draft model (--no-draft); a drafted run is sized for one.
# - Where a plan's total equals the free memory, the planner sized the KV pool to what the GPU has left: "fits" there means the pool the planner could give the 64 users, the same at 1,024 and 4,096.
# - The L4's 14 GiB of RAM is the preset's; a machine with more would take the Nemotron-H layout's kestrel and swift levels with experts in RAM.
# - Smaller checkpoints of these families exist but the engine refuses them today: Gemma 4 E2B and E4B (and nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-BF16, the same architecture): per-layer embeddings.
#   tencent/WeMM-Ecom-2B, -4B and -9B and microsoft/Fara1.5-4B are the same Qwen3.5 layout as the 0.8B row and larger.
