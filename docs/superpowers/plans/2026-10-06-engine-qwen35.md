# glyd-engine runs Qwen3.5: implementation plan

> **For agentic workers:** steps use checkboxes (`- [ ]`). Each task is test-first: write the check, see it fail, make it pass, commit. One task, one PR (host tasks may share a PR where they share a file).

**Goal:** `glyd-engine` runs Qwen3.5 dense models (0.8B to 27B, Qwen3.6-27B and Qwen3.8-27B) from Glyd-packed weights, text only, and takes them from vLLM on each GPU where it is at least as fast as vLLM 0.30.0 at 1 to 256 users and uses less memory. Then Gemma 4.

**Spec:** `docs/superpowers/specs/2026-10-06-engine-qwen35-design.md`.

**Architecture:** a second forward pass (`model35.rs`) beside Qwen3's, sharing the engine's frame (driver, library, Hub, pack, tokenizer, sampler, server, CLI); `qwen35.rs` holds the config, the layer schedule and the weight map; `qwen35_ref.rs` (development build) the CPU reference the kernels are checked against; `kernels/qwen35.cu` the new kernels, all our own.

**Tech stack:** Rust stable, CUDA C++ (nvcc 13, sm_80/86/89/90a/100/120), the library's C API 15 (16 for the head-256 lossless cache later), vLLM 0.30.0 as the reference and the yardstick on pods only.

## Global constraints

- **2026 models only**, for every check, fixture, example and number: Qwen3.5-0.8B/-2B/-4B/-9B/-27B, Qwen3.6-27B, Qwen3.8-27B; Gemma 4 for its phase. No Qwen3, Llama or Mistral anywhere in this work.
- **Nothing runs on the Mac.** The Mac reads code, edits, uses git and gh, and may `cargo check`. Tests run in CI (`ci.yml`'s `engine` job: `cargo test --release -p glyd-engine` with and without the default features, and `check_wheel.py --engine-source`); anything that runs a model or a GPU kernel runs on a Runpod pod.
- **Pods:** `$S/rp_run.sh` (`$S` = the old session scratchpad `/private/tmp/claude-501/-Users-suryakoritala-alatirok/a9feedc0-e067-4d76-bca6-e4b6b9538345/scratchpad`), one batched job per pod, `MAX_MIN` set, the pod deleted on exit, the job run with `run_in_background`; the cheapest GPU that answers (RTX 4090 for Ada); the owner approves each run's spend before launch. Four runs in all (Runs 1 to 4 below).
- **Git:** private repo only (remote `private`, glyd-gpu-private). Branch from `private/main`, PR, CI green, merge with `gh pr merge --merge --admin` after review. Commits as `git -c user.name="Surya Koritala" -c user.email="suryakoritala1324@gmail.com" commit -s -m "<one plain line>"`, no attribution lines.
- **Release build's words:** every string a release build compiles (`qwen35.rs`, `model35.rs`, server and CLI changes) passes `check_wheel.py --engine-source`: no method words (`tile`, `page`, `slot`, `pool`, `stage`, `split`, ...), no tuning variable. Development-only code (`qwen35_ref.rs`, the new checks) sits under `#[cfg(feature = "dev")]`.
- **Exact weights:** a packed matrix unpacks to the checkpoint's bits; no check is loosened. The forward pass is checked against vLLM within vLLM's own run-to-run floor.
- **Our own kernels only:** FLA, vLLM's Triton kernels, FlashInfer, causal-conv1d and FlashAttention are read and timed as yardsticks in scratch directories; nothing is copied, vendored, linked or fetched.
- **Qwen3's outputs do not change:** the Qwen3 path's kernels keep their bits (`kcheck` and the fixtures pass unchanged at every task).

## Phase A: host work (CI only)

### Task 1: Config of Qwen3.5 (`qwen3_5`, `qwen3_5_text`)

**Files:** create `glyd-engine/src/qwen35.rs`, `glyd-engine/tests/fixtures/qwen35_configs.json` (the Hub's `config.json` of Qwen3.5-0.8B, -2B, -4B, -9B, -27B, -35B-A3B, Qwen3.6-27B, Qwen3.8-27B, Qwen3.8-2.4T-A95B, fetched with curl, 2-3 s apart); modify `glyd-engine/src/lib.rs` (`pub mod qwen35;`), `glyd-engine/src/weights.rs` (the eos rule as a shared function).

**Interface:**
```rust
pub enum Kind { Linear, Full }
pub struct Config35 { hidden, layers, heads, kv_heads, head_dim, inter, vocab, eps, rope_theta, rotary_dim, max_pos, tie, eos,
                      kinds: Vec<Kind>, lin_k_heads, lin_v_heads, lin_k_dim, lin_v_dim, conv_kernel, mtp_layers, prefix: &'static str, vision: bool }
impl Config35 { pub fn load(dir) -> Result<Config35>; pub fn parse(text, label, generation: Option<&str>) -> Result<Config35> }
pub fn eos_ids(config: &Value, generation: Option<&str>) -> Vec<i64>   // weights.rs, Qwen3's and Qwen3.5's
```

- [ ] Tests: every dense config parses with its numbers (9B: 4096, 32, 16, 4, 256, 12288, 248320, rotary 64, theta 1e7, linear 16/32/128/128, kernel 4, `model.language_model.`, untied; 0.8B tied, linear 16/16; Qwen3.5-27B, Qwen3.6-27B and Qwen3.8-27B 64 layers, 24 query to 4 KV heads, 48 value heads); the flat `qwen3_5_text` form (a `Qwen3_5ForCausalLM` made from the 9B's `text_config`) parses with prefix `model.`; refused with a reason that says so: `qwen3_5_moe` and `qwen3_5_moe_text` (MoE comes later), `output_gate_type` other than absent, `silu` or `swish`, zero query heads, `rope_type` other than default, `attention_bias`, `hidden_act` other than silu, `attn_output_gate: false`, `mamba_ssm_dtype` other than float32, `layer_types` of the wrong length or kind, value heads not a multiple of key heads, `mrope_section` not summing to half the rotary dims; `generation_config.json`'s eos list wins over the config's.
- [ ] Implement; Qwen3's `Config::parse` uses `eos_ids` unchanged in behaviour (its tests pass as they are).

### Task 2: The layer schedule and the per-sequence sizes

**Files:** `glyd-engine/src/qwen35.rs`.

**Interface:** `Config35::schedule() -> Vec<(Kind, usize)>` (the kind and the index within it: the state index of a linear layer, the KV layer of a full one), `linear_layers()`, `full_layers()`, `conv_dim()`, `state_bytes()` (fp32 states and bf16 conv states of one sequence), `kv_bytes_per_token()` (bf16).

- [ ] Tests: 9B's schedule is `L L L F` x 8 with indices 0..23 and 0..7; `layer_types` absent gives `full_attention_interval`'s (default 4) pattern; sizes as the spec's table (9B: 48 MiB + 1,179,648 bytes, 32 KiB a token; 0.8B: 18 MiB + 663,552 bytes, 12 KiB; 27B: 144 MiB, 64 KiB).

### Task 3: The weight map

**Files:** `glyd-engine/src/qwen35.rs`, `glyd-engine/tests/fixtures/qwen35_tensors.json` (names, dtypes and shapes of Qwen3.5-0.8B and -9B, from the Hub's safetensors headers by HTTP range requests).

**Interface:**
```rust
pub struct Pack35 { pub key: String, pub parts: Vec<(String, usize)>, pub cols: usize }   // key: the first part's module; parts: (tensor name, rows)
impl Pack35 { pub fn rows(&self) -> usize; pub fn packable(&self) -> bool }               // every part's rows % 64 == 0 && cols % 16 == 0: the packer merges a group only when each member is packable
pub struct Tensor35 { pub name: String, pub dtype: &'static str, pub shape: Vec<u64> }
impl Config35 {
    pub fn packs(&self) -> Vec<Pack35>;      // the packable ones only, per layer in order (full: q_proj+k_proj+v_proj, o_proj; linear: in_proj_qkv+in_proj_z, in_proj_b+in_proj_a, out_proj; then gate_proj+up_proj, down_proj), then embed, lm_head (untied)
    pub fn kept(&self) -> Vec<Tensor35>;     // norms, conv1d, A_log, dt_bias, the gated norm, and the parts of a pack that is not packable
    pub fn check(&self, have: &[(String, String, Vec<u64>)]) -> Result<()>;   // every wanted tensor present with its dtype and shape; nothing else but the skipped classes
}
pub fn skipped(name: &str) -> bool          // model.visual.*, mtp.*: not loaded in this phase
```

- [ ] Tests: the 0.8B's and the 9B's real indexes pass `check`; the 9B's packs have the spec's shapes (10240, 4096, 12288 + 64, 4096, 24576 x 4096 and 4096 x 12288; LM head 248320 x 4096); `in_proj_b` + `in_proj_a` is not packed on any dense model (each part under 64 rows: 16, 32 or 48) and both parts are kept; a missing tensor, a wrong shape, a wrong dtype and an unknown tensor are each refused, named; visual and MTP tensors are skipped and counted.

### Task 4: The DeltaNet recurrent step, CPU reference

**Files:** create `glyd-engine/src/qwen35_ref.rs` (`#[cfg(feature = "dev")] pub mod qwen35_ref;` in `lib.rs`).

**Interface (fp32, rounded to bf16 only where vLLM 0.30.0's decode step stores bf16: the conv output after SiLU, beta, the head's output, the gated norm's weight and output; q and k l2-normed in fp32, unrounded):**
```rust
pub fn bf16(x: f32) -> f32; pub fn silu(x: f32) -> f32; pub fn sigmoid(x: f32) -> f32; pub fn softplus(x: f32) -> f32   // torch's: x above 20 is x
pub fn conv_step(w: &[f32], state: &mut [f32], x: &[f32], kernel: usize) -> Vec<f32>          // silu(causal depthwise conv), state: the last kernel-1 inputs of each channel
pub fn l2norm(x: &mut [f32])                                                                    // x * rsqrt(sum x^2 + 1e-6)
pub fn delta_step(s: &mut [f32], q: &[f32], k: &[f32], v: &[f32], g: f32, beta: f32, dk: usize, dv: usize) -> Vec<f32>
pub fn gated_norm(o: &[f32], z: &[f32], w: &[f32], eps: f32) -> Vec<f32>
pub struct Dims { pub nk, nv, dk, dv, kernel }
pub struct LinearParams { pub conv: Vec<f32>, pub a_log: Vec<f32>, pub dt_bias: Vec<f32>, pub norm: Vec<f32>, pub eps: f32 }
pub struct LinearState { pub conv: Vec<f32>, pub s: Vec<f32> }
pub fn mixer_step(d: &Dims, p: &LinearParams, st: &mut LinearState, qkv: &[f32], z: &[f32], b: &[f32], a: &[f32]) -> Vec<f32>   // out_proj's input for one token
```

- [ ] Tests: write then read (beta 1, g 0, a unit key: reading with the key gives the value back); the delta rule overwrites (two writes to one key: the second value is read back, not the sum); the decay (g = ln 0.5 halves what is read); a zero state and a zero value give zero; the conv step token by token equals the whole causal convolution of the sequence with zero history; value head h reads key head h / r; the gated norm in vLLM's order (`bf16(norm(o) * bf16(w) * silu(z))`, one rounding); the l2 norm left unrounded; `mixer_step` over a few tokens on small dims equals the pieces composed by hand.

### Task 5: The chunked form, CPU reference

**Files:** `glyd-engine/src/qwen35_ref.rs`.

**Interface:** `pub fn delta_chunked(s: &mut [f32], q, k, v: &[f32], g, beta: &[f32], t: usize, dk, dv, chunk: usize) -> Vec<f32>` (one value head, `t` tokens, the WY form: cumulative decays, `(I + tril(beta K K^T, -1))^-1` by forward substitution, the chunk's outputs and the carried state).

- [ ] Tests: equal to `t` calls of `delta_step` within 1e-5 relative (outputs and final state) for t in {1, 63, 64, 65, 200} and chunk 64 and 16, random inputs with realistic `g` (exp(g) in 0.9..1) and l2-normed keys; the state carried across two calls equals one call over the joined tokens.

## Phase C: kernels and the forward pass

Kernels, each with its check:
- [ ] `rmsnorm` / `rmsnorm_add` with `1 + w` (a parameter; Qwen3's launch passes 0 and keeps its bits);
- [ ] q and gate apart, q/k norm (`1 + w`) and rotary on the first 64 of 256 dims;
- [ ] prompt attention at head 256 (causal, our flash form, the GQA group `heads / kv_heads` a parameter: `kcheck35` checks 4 (0.8B to 9B) and 6 (the 27Bs)) and decode attention over bf16 16-token pages (split along the context for long ones), both with `* sigmoid(gate)` in the epilogue: against an fp32 product within bf16 rounding;

- [ ] the gated delta rule's decode step with the gated norm and `silu(z)` in the epilogue: against `delta_step` + `gated_norm`;
- [ ] the chunked delta rule for prompts: against `delta_chunked` and against the decode step run token by token.
